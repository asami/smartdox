# SmartDox

SmartDox is an open-source **Literate Modeling and Knowledge Documentation Language**  
designed for the AI era. It enables a single document to function simultaneously as:

- human-readable technical documentation,
- a structured knowledge representation,
- an ontology-linked data source (JSON-LD / RDF),
- and the foundation of a generated HTML documentation site.

SmartDox combines ideas from Markdown, Org-mode, and AsciiDoc while introducing  
semantic structure tailored for modeling, knowledge engineering, and AI-assisted  
development workflows.

SmartDox powers the documentation and knowledge base behind  
[SimpleModeling.org](https://www.simplemodeling.org).

---

## Key Features

### 📝 1. Literate Modeling Language  
A document-centric modeling style using structured sections:

- `HEAD`, `SUMMARY`, `ABSTRACT`, `LEAD`, `REMARKS`, etc.  
- Human-friendly, Markdown-like syntax  
- Designed for domain modeling and Literate Model-Driven Development (LMDD)  
- Supports article-style and specification-style writing

---

### 📚 2. Knowledge Description Language (KDL)  

SmartDox documents include a rich structural layer that can be exported in multiple formats:

- **XML** — a lossless, full-document representation of the SmartDox structure,  
  designed for external tools to inspect and manipulate the entire document tree.  
- **JSON** — focused, machine-readable projections of the structure for general tooling.  
- **YAML** — human-readable structured views suitable for configuration, CI/CD, or review.  
- **JSON-LD** — ontology-linked semantic data for knowledge graphs and linked data.

In typical usage, XML is used as the **canonical external representation of a whole  
SmartDox document**, while JSON / YAML / JSON-LD are used as **purpose-specific  
exports of particular parts or views** of the document (e.g., metadata, glossary,  
domain model, or article summaries).

This structured layer is generated by SmartDox’s internal extraction engine  
and can be consumed by downstream tools, knowledge bases, static-site  
generators, and AI systems.

---

### 🌐 3. Human + AI Dual-Purpose Documentation  
A SmartDox file produces **both**:

1. **Human-readable HTML documentation sites**
   - Full Antora integration  
   - Used by SimpleModeling.org as its main content format  

2. **AI-readable structured knowledge**
   - XML / JSON / YAML / JSON-LD export  
   - Ontology-based metadata and semantic markup  
   - Ideal for RAG, knowledge graphs, semantic search, and intelligent agents  

SmartDox serves as a unified source format for documentation, knowledge,  
modeling, and AI-assisted development.

---

### 🔧 4. Tool Integration  
- **Internal structured-extraction engine** for XML, JSON, YAML, and JSON-LD  
- **Cozy** for code generation (Scala / TypeScript)  
- **Antora** for HTML site generation  
- **RDF/JSON-LD tools** for knowledge-base and graph construction  
- **AI/LLM support** via semantically structured, machine-readable exports

---

### 🌏 5. Multilingual Documentation Support (Multi-Locale)

SmartDox is built on a fully **multi-locale internal model**, capable of  
representing any number of languages in parallel. Each section, term, or  
metadata field may hold language-tagged variants, enabling precise  
internationalized documentation and knowledge representation.

Although current official usage (e.g., SimpleModeling.org) adopts an  
**EN/JA bilingual writing style**, this is a convention—not a limitation.  
The SmartDox model can naturally support additional languages (e.g., zh, fr,  
de, ko) within the same document or knowledge base.

This multilingual structure enhances:

- AI alignment across parallel texts  
- multilingual JSON-LD/RDF knowledge graphs  
- international documentation workflows  
- Antora-based multilingual site generation

Multilingual content is treated as a first-class semantic feature of SmartDox.

## PDF Dependency Image

`dox pdf` / `cozy pdf` prefers locally installed tools. If Chrome/Chromium,
`asciidoctor-pdf`, or a Japanese TeX environment is not available locally, PDF
generation can run through the SmartDox PDF dependency image.

Build the image:

```bash
docker build -t simplemodeling/smartdox-pdf:latest docker/smartdox-pdf
```

The image includes `asciidoctor-pdf`, Japanese TeX packages, CJK fonts, and
Kroki. Docker-based Asciidoctor PDF generation uses a bundled IPA Gothic TTF
theme so Japanese text is rendered without local font setup.
`cozy pdf` / `dox pdf` uses the LaTeX renderer by default. The LaTeX renderer
uses SmartDox -> LaTeX -> LuaLaTeX by default, with an optional UpLaTeX ->
`dvipdfmx` route. The image warms both TeX routes during build so the first
runtime PDF generation does not pay the format or font cache cost. Local tools
remain the default in `dependency-mode=auto`.

Diagram generation supports fenced `plantuml` blocks and uses SmartDox's local
Kroki cache. When
`SMARTDOX_KROKI_SERVER_URL` is not set, SmartDox invokes the same dependency
image in command mode for each uncached Kroki rendering. This makes diagram PDF
generation work after installation without asking users to run a separate
service. For performance-oriented environments, run the image as a Kroki server
and point SmartDox at it.

Examples:

```bash
cozy pdf system.dox
cozy pdf system.dox --renderer latex
cozy pdf system.dox --renderer latex --latex-engine uplatex
cozy pdf system.dox --renderer latex --latex-format business \
  --latex-date 2026-06-02 --latex-affiliation "Knowledge Hub" --latex-author "Taro Yamada"
cozy pdf system.dox --renderer chrome-headless
cozy pdf system.dox --renderer asciidoc
cozy pdf system.dox --dependency-mode docker
cozy pdf system.dox --renderer latex --dependency-mode docker
cozy pdf system.dox --renderer latex --latex-engine uplatex --dependency-mode docker
cozy pdf system.dox --renderer asciidoc --dependency-mode docker
cozy pdf system.dox --docker-image simplemodeling/smartdox-pdf:latest
```

Kroki command mode is the default for uncached diagrams:

```bash
cozy pdf system.dox
```

Kroki server mode is optional:

```bash
docker run --rm -p 9609:8000 simplemodeling/smartdox-pdf:latest kroki-server
export SMARTDOX_KROKI_SERVER_URL=http://localhost:9609
cozy pdf system.dox
```

The Kroki command image can be changed with `SMARTDOX_KROKI_DOCKER_IMAGE`.
If it is not set, `SMARTDOX_PDF_DOCKER_IMAGE` is used, then
`simplemodeling/smartdox-pdf:latest`.

`--dependency-mode local` disables Docker fallback and fails if the local tool
is missing. `--dependency-mode docker` forces Docker even when local tools
exist.

`--latex-format business` renders a business-document title block: centered
document title, one blank line, right-aligned date, right-aligned affiliation
and author, one blank line, then the body. Without `--latex-format`, the
standard LaTeX title block is used.

For the business layout, date, affiliation, and author can be written in the
SmartDox document head. All three are optional; omitted values are not rendered.
Command-line values override document metadata.

```text
Business Report
===============

date = "2026-06-02"
affiliation = "Knowledge Hub"
author = "Taro Yamada"

Body starts here.
```

`published_at` / `publishedAt` are accepted as the canonical publication date
property, and `organization` is accepted as the canonical affiliation property.

When invoked through Cozy, the same PDF options can be set in
`$HOME/.cozy/config.yaml` or `$PWD/.cozy/config.yaml`. Cozy reads these files
and passes the effective operation properties to SmartDox. Local working-
directory config overrides home config; command-line options override both.

```yaml
pdf:
  latex-format: business
```
